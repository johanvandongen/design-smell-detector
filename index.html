Understanding the visualization

This tool visualizes dependencies between classes in a Java codebase and identifies cyclic dependencies. The following sections explain how cycles are detected and how to interpret the different dependency types.

1. Detecting cyclic dependencies

The tool uses Strongly Connected Components (SCCs) to identify groups of classes that form cyclic dependencies.

A strongly connected component is a maximal group of nodes in which every node can reach every other node by following directed edges.

Example: A strongly connected component

A can reach B, B can reach C, and C can reach A. Therefore, all three nodes belong to the same SCC.

An SCC can contain multiple cycles, not just one. For example, a group of classes may contain several different paths that eventually lead back to their starting point.

Important: An SCC represents the entire interconnected group, not each individual cycle. A single SCC can therefore contain several overlapping cycles.

2. Understanding dependency types

The visualization uses different types of edges to represent relationships between classes. Some edges represent dependencies directly detected in the source code, while others are derived by combining these dependencies to provide a clearer overview at the class level.

Direct dependencies

Direct dependencies represent relationships detected at the method or field level in the Java source code. These edges describe how individual parts of a class depend on other classes.

These are

  • Paramerizes
  • Typed
  • Returns
  • Invokes
  • Instantiates
  • Specializes
  • Implements

Composed class-level dependencies

When multiple methods or fields in a class depend on another class, displaying every individual dependency can make the visualization cluttered. To address this, the tool combines certain method-level dependencies into higher-level class-level relationships. These composed edges provide a more concise overview of dependencies between classes.

Composed edges are derived from the direct dependencies. They are not additionally detected in the source code.

These are

  • Accepts (composed from paramerizes edges)
  • Holds (composed from typed edges)
  • Produces (composed from returns edges)
  • Calls (composed from invokes edges)
  • Constructs (composed from instantiates edges)

CD-smell edges

CD-smell edges are special analytical edges added by the tool to make strongly connected components easier to identify visually.

Once an SCC has been detected, the tool adds CD-smell edges between the nodes belonging to that component. These edges highlight the relationship between classes that participate in the same cyclic dependency.

Unlike the other edges, CD-smell edges do not represent dependencies found in the Java source code. They are visualization aids derived from the SCC analysis.

3. Dependency type examples

Instantiates (Constructs)

A method creates an instance of another class.

class A {
    void create() {
        B item = new B();
    }
}

The direct instantiates dependency is represented at the class level as A constructs B.

Typed (Holds)

A field or variable is declared with another class as its type.

class A {
    private B item;
}

The direct typed dependency is represented at the class level as A holds B.

Parameterizes (Accepts)

A method accepts another class as a parameter.

class A {
    void process(B item) {
        // ...
    }
}

The direct parameterizes dependency is represented at the class level as A accepts B.

Returns (Returns(cls))

A method declares another class as its return type.

class A {
    B create() {
        return new B();
    }
}

The direct returns dependency is represented at the class level as A returns(cls) B.

Invokes (Constructs)

A method invokes a method belonging to another class.

class A {
    void process(B item) {
        item.execute();
    }
}

The direct invokes dependency is represented at the class level as A calls B.

Implements

A class implements an interface.

class A implements B {
}

Specializes

A class extends another class through inheritance.

class A extends B {
}

Multiple dependencies example

Example 
class A {
    private B item;

    void process(B other) {
        other.execute();
    }

    B create() {
        return new B();
    }
}

Class A has several dependencies on B:

  • Holds B
  • Accepts B
  • Calls B
  • Produces B
  • Constructs B
