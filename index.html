Understanding the visualization

This tool visualizes dependencies between classes in a Java codebase and identifies cyclic dependencies. The following sections explain how cycles are detected and how to interpret the different dependency types.

1. Detecting cyclic dependencies

The tool uses Strongly Connected Components (SCCs) to identify groups of classes that form cyclic dependencies.

A strongly connected component is a maximal group of nodes in which every node can reach every other node by following directed edges.

Example: A strongly connected component
A → B → C → A

A can reach B, B can reach C, and C can reach A. Therefore, all three nodes belong to the same SCC.

An SCC can contain multiple cycles, not just one. For example, a group of classes may contain several different paths that eventually lead back to their starting point.

Important: An SCC represents the entire interconnected group, not each individual cycle. A single SCC can therefore contain several overlapping cycles.

2. Understanding dependency types

The arrows in the visualization are directed. An arrow from class A to class B means that A depends on B in some way. The tool distinguishes between several types of dependencies.

Holds (Typed)

A class holds a reference to another class through a field.

class A {
        private B item;
    }

A holds B because it declares a field of type B.

Accepts (Parameterizes)

A method accepts another class as a parameter.

class A {
        void process(B item) {
            // ...
        }
    }

A accepts B because its method has a parameter of type B.

Calls (Invokes)

A method invokes a method belonging to another class.

class A {
        void process(B item) {
            item.execute();
        }
    }

A calls B because its method invokes execute() on an instance of B.

Constructs (Instantiates)

A method creates an instance of another class.

class A {
        void create() {
            B item = new B();
        }
    }

A constructs B because it creates an instance using new B().

Produces (Returns)

A method returns an instance of another class.

class A {
        B create() {
            return new B();
        }
    }

A produces B because its method declares B as its return type.

3. Method-level and class-level dependencies

Dependencies are detected at the method and field level, but the visualization displays them at the class level.

Method-level dependencies

These describe relationships between individual methods or fields. For example, a method in class A might call a method in class B.

Class-level dependencies

These aggregate dependencies between two classes. If multiple methods or fields in A depend on B, their dependencies are represented as edges between A and B.

Example 
class A {
        private B item;

        void process(B other) {
            other.execute();
        }

        B create() {
            return new B();
        }
    }

Class A has several dependencies on B:

  • Holds B
  • Accepts B
  • Calls B
  • Produces B
  • Constructs B
A → B Holds · Accepts · Calls · Produces · Constructs

4. Interpreting the visualization

  • Nodes represent classes.
  • Directed edges represent dependencies between classes.
  • Edge labels indicate the type of dependency.
  • Highlighted classes belong to a strongly connected component and participate in a cyclic dependency.

By inspecting an SCC, you can explore the individual dependencies contributing to the cycle and investigate possible refactorings.
